# P4 分工预案与全项目最终测试计划

> 编制日期：2026-11-06。**这是前瞻性计划，不是 P3 阶段复核、P4 Contract Gate 执行记录或测试通过报告。** P3 尚未实现；P2 可复核基线及 P3 的准确启动条件见 [P2 阶段复核与 P3 分工计划](P2阶段复核与P3分工计划.md)，前一阶段的分工方式见 [P1 阶段复核与 P2 分工计划](P1阶段复核与P2分工计划.md)。需求与原阶段边界分别以 [课程任务三](course/课程任务.md)第 205–301 行和 [原总计划](../Q%26A_Assistant/plan-q-a-kbmanagement-exe-go-sharded-umbrella.md)§7–9 为准。本文区分“P4 阶段退出”与“P5/Agent Insight 集成完成后的项目总验收”；**不能用 P4 两普通站点的通过结果代替课程第 8 项真实 Agent Insight 集成。**

## 一、启动前置与边界

1. **先收 P3**：P3 Contract Gate、A1 冲突解决短补与模型/SSE 后端、A2 问答/向量核心、用户明确允许后启动的 B，以及真实适配器跨流和浏览器联调，均提交可复核证据；未完成项列为阻断，不从 P2 的 337 passed/2 skipped 历史数字推断 P3 已交付。P3 的协议/版本决定和已知局限交接给 P4；P4 不代行 P3 的大块模型/问答实现。
2. **短 P4 Contract Gate（共享 owner）**：确认 P3 真正生成的 DTO、OpenAPI、事件版本、SDK、Job/SSE 语义与现有反馈接口；冻结验收查询/报告格式、反馈→问题→补库→复测的状态转换及分发检查输出。先写兼容性/权限/负例，生成产物后跑 Gate；A1/A2 不得在 Gate 未通过时实施 P4 业务。若接口已有且足够，复用并冻结，不为“阶段”强制升级协议。
3. **A1/A2 平行**：后端各用冻结契约、fake/录制协议独立开发与自测；A1 提供工程与持久反馈闭环，A2 提供真实语料评测及质量审计。两组均提交独立退出报告，再由复核 owner 在 `tests/integration/cross_stream/` 组织真适配器交叉验证。
4. **B 后启动**：只有用户获知 **P4-A1 和 P4-A2 均已完成**且明确同意启动 P4-B，B 才做前端验收与必要的前端修复。B 只通过生成 SDK、HTTP/SSE 调用后端；不读 SQLite/模型缓存、不复制后端权限和反馈状态机。
5. **P4 结束即停**：P4 不擅自开始 P5。课程第 8 项 Agent Insight 真集成，以及可选 Go 桌面端，是 P5 交付；项目总验收安排在 P5 完成后另起一次完整执行。若 Agent Insight 仓库/版本/运行条件缺失，明确“第 8 项未验收”，不得把两个普通网页叫作它；可选 Go 若不实施，在总验收范围表标“未纳入/未交付”，不能写“通过”。

## 三、项目总验收：P5 完成后再执行

**执行点**：P4 阶段末先做 P4 回归；P5 Gate、P5-A1/A2/B 的实际交付、真实 Agent Insight 适配（原计划将其留 P5）、可选 Go 的范围决定均结束后，重新跑下述完整矩阵。不要复用 P4 通过数字充当 P5 最终证据。最终执行者为复核 owner，A1/A2/B 对其 owner 的失败修复，用户对真实 WebUI/宿主及其账号环境做见证。任何一项受环境阻断明确列“未验收”，不得折算为通过率。

### 验收覆盖与通过口径

- **需求覆盖目标：100% 可追溯**。给课程任务三第 225–239 行的 8 个维度，以及额外的单/多/auto 选库、本地/外接模型、CLI/API 独立可用、分发不带权重分别分配唯一 case_id、正例/负例/边界、owner、自动/人工类别、预期/实际、执行日期和证据；**覆盖**表示每条有测试及结果，不等于通过。第 8 项必须是 Agent Insight 的真实版本、真实页面和真实调用。
- **高风险语义目标：100% 已列出的确定性用例通过**：租户/权限隔离、路径/上传边界、版本和引用固定、并发发布/冲突/回滚、幂等与重复计费、模型身份/local_only/凭据、拒答的引用真实性、SSE 终态/重放/取消、隐式下载/打包；不允许靠总体平均数冲淡任一失败。每个修复至少一条重现旧故障的回归及一条邻近边界例。
- **代码覆盖目标（不是完成承诺）**：为 Python/TS 安装并锁定适当覆盖工具后分别报告行/分支覆盖率及按包拆分；力争核心业务行和分支均趋近 100%，实际门槛在 P4 Gate 根据可执行分支/外部适配边界与基线确定并记录。优先达到关键状态机/权限/版本/幂等/指标计算 **100% 可测试分支**，其余代码每条不可测分支都列出原因和手工/live 补证；覆盖率只计算实际执行的生产代码、排除规则事先公布，禁止删代码或广泛 `pragma: no cover` 冲数字。浏览器行为、真实模型质量、第三方运行时及用户体验不能由行覆盖率证明。
- **运行覆盖目标：100% 计划用例有可追踪结果**（pass/fail/blocked/skip 各自统计）；发布门要求 P0 阻断场景 0 fail、0 无理由 skip，8 维逐项给出判断；无模型、无 OCR/旧格式转换器、无第二浏览器、无 Agent Insight 环境时不得把跳过记通过。质量指标在固定保留集单独判门，不与确定性代码覆盖相混。

### 评测数据与统计口径（预注册，不填写假成绩）

1. 用户提供或授权真实业务文档；由 A2 建 `manifest.json`（文件路径/哈希/格式/版本/许可）、带 case_id 的 `cases.jsonl` 和 `qrels.json`（相关 kb、revision、locator、可答/拒答、歧义、会话组）。含至少 60 道可答、20 道不可答/证据不足、10 组三轮以上对话；额外标注多库联合取证、改写、精确标识和冲突证据。题库按**来源文档+会话组**划调参/保留集；冻结保留集后不能用其调参再宣称独立。
2. 在**相同问题、权限和固定版本组合**上对照 BM25、向量、融合、融合+重排；每次仅变一个变量。记录每题候选库、实际搜过的库、证据片段、错误类型（选库/召回/重排/生成/支持/引用/拒答）；不混加不同库的原始 BM25 或不同 embedding profile 原始向量分数。
3. 统一指标：Precision@k 分母为 k（不足 k 按缺失）、Recall@k 分母为已标注相关证据数、MRR@k/nDCG@k 按固定 qrels 计算；无答案题不混入正例 Recall，另报拒答正确率/错误作答率。选库 precision/recall、必要库召回、无匹配/澄清准确率及每库证据覆盖单列。预先标注的异写子集验证融合增益，同时给全量与分组结果；不能只报平均值。
4. 引用 100% 有效是**验收集目标**：机械检查 kb/version/revision/locator 可解析且当前用户有权限，人工检查引用原文确实支持每个事实；发现编造/错引即列阻断案例、修复重测，不将“本次样本零错”扩展为普遍保证。分别报告模型 call 的 runtime、摘要、策略、费用/预算与 cold/warm p50/p95；不把文件大小当成内存适配证明。
