## P3 启动前置与顺序

**严格同 P2 模式**：本轮 P2 审查与测试闭环 → **短 P3 Contract Gate（先冻结原 §3.3 冲突三策略及模型/问答共享契约）** → Gate provider/consumer/兼容门绿并冻结 → P3-A1 先做冲突服务端短补与独立验收，同时 P3-A2 仅可用冻结 DTO/fake 准备独立算法；**P3 模型 A1/A2/B 业务均在三策略 Gate 纳入前不得启动** → A1/A2 模型后端并行、只依赖冻结端口 → 后端真实适配器跨流验收 → 仅在用户获知 A1/A2 均完成并明确允许后开始 P3-B（先冲突 UI、再模型页/Widget） → 真实 HTTP/SSE 与浏览器联调 → 阶段末停止，不擅自启动 P4。A1/A2 互不审批，不交叉修改对方 owner 文件；B 不导入后端内部实现。冻结契约变更须回 Gate 决策，不能阶段中单组修改 DTO/schema。
